# MPC Professional IT Career Program

**Mogadishu Professional Certificate (MPC) — Soobe, Mogadishu, Somalia**

One-Year Curriculum Model · Course Catalog · Certificate Framework

*Revision 2.0 adds a Frontend Development course before web development, a Git & GitHub course with a version-control requirement across every programming subject, and Python programming. Django moves to the Level 2 specialisation layer, and Advanced Excel is absorbed into the Data Analysis specialisation, to hold the program at 576 hours in one year.*

Version 2.0 — September 2026

## 1. Purpose of This Document

This document defines a complete, teachable model for MPC's one-year IT program. It answers four questions:

1. **What can a graduate actually do?** — a written job profile, not a topic list.
2. **What courses exist, in what order, and for how many hours?**
3. **How is each course assessed, and when is a certificate issued?**
4. **What is missing from the current MPC offering, and what should be added?**

Every course in this model is a standalone, certificate-bearing unit. A student may enrol in a single course and receive an MPC Course Certificate for it. Students who complete groups of courses receive higher stage awards, up to the full Professional Diploma.

## 2. The Graduate Profile — What a Student Can Do After One Year

The program is built backwards from a single sentence:

> **A graduate can walk into a small or medium Somali business and take full responsibility for its computers, its office network, its documents, and its website.**

Broken into verifiable job tasks, the graduate can:

**Computers and operating systems**

- Assemble a desktop PC, identify every component, and diagnose a machine that will not boot.
- Install and configure Windows 10/11 from USB media, including drivers, updates, user accounts and activation.
- Install and configure Linux (Ubuntu Server and Ubuntu Desktop), including partitioning, users, permissions and package management.
- Dual-boot a machine, create a bootable recovery USB, and image or clone a working system.
- Diagnose and repair common faults: no display, no boot, slow performance, virus infection, corrupted profile, failing disk, overheating, driver conflicts.
- Back up and restore user data, and recover files from a failed installation.

**Office network and printing**

- Plan and cable a small office network: terminate UTP cable, crimp RJ45, test with a cable tester, mount a patch panel and switch.
- Configure a router, DHCP scope, static IP plan, subnet mask and gateway for a 10–50 user office.
- Configure Wi-Fi with WPA2/WPA3, guest isolation and channel planning.
- Set up file sharing and shared folders with permissions, on Windows and on Linux (Samba).
- Install a network printer, share it, install drivers on all client machines and fix common printing faults.
- Troubleshoot connectivity with ping, ipconfig/ip, tracert, nslookup and a structured method.

**Documents and office software**

- Produce professional documents in Word: letterhead, multi-section reports, table of contents, mail merge, styles, templates.
- Build working spreadsheets in Excel: formulas, absolute references, lookup functions, pivot tables, charts, data validation, printable reports.
- Design and deliver a presentation in PowerPoint.
- Create, edit, merge, split, protect and fill PDF forms; scan and OCR paper documents.
- Manage files and records: naming conventions, folder structures, versioning, cloud sync and shared drives.
- Type accurately in both Latin and Somali text, and format Arabic-script or right-to-left content when required.

**Web design and web development**

- Build a responsive multi-page website from scratch with HTML5 and CSS3, working correctly on phone and desktop.
- Add interactivity with JavaScript: form validation, image sliders, menus, dynamic content.
- Build a small database-driven web application with PHP and MySQL: login, add/edit/delete records, search, reports (for example a student registration system, a shop inventory, a clinic appointment book).
- Register a domain name and rent hosting, configure DNS records, upload a site by FTP/cPanel, install an SSL certificate, and set up a business email address.
- Install and customise WordPress for a client who needs a site quickly.

**Programming and version control**

- Write working programs in Python: variables, conditions, loops, functions, lists and dictionaries, files, error handling and basic object-oriented code.
- Automate everyday IT work with Python scripts: renaming files in bulk, reading and writing CSV, checking whether servers are reachable, parsing log files, sending automated reports.
- Use Git for every piece of code they write: initialise a repository, commit with meaningful messages, branch, merge, resolve a conflict, and recover previous versions.
- Publish and collaborate on GitHub: remote repositories, push and pull, pull requests, issues, README files, and a public profile that an employer can inspect.

**Security and professional practice**

- Apply basic security: strong passwords, password manager, MFA, patching, antivirus, safe browsing, phishing recognition, and a simple backup routine.
- Log, prioritise and close support tickets, and write a clear fault report.
- Write a CV, present a portfolio of real projects, and handle a technical interview.

**Target entry-level roles:** IT Support Technician · Computer Lab Technician · Network Support Technician · Office IT Officer · Junior Web Developer / Frontend Developer · ISP or Internet-café Support Staff · Data Entry and Office Administration Officer.

## 3. Review of MPC's Current Offering

### 3.1 What is already right

| Strength | Comment |
|---|---|
| Two entry pathways (12-month and 6-month) | Correct market fit — one for school leavers, one for career switchers who need speed. |
| Modular structure with portfolio evidence per module | This is the right pedagogy. Keep it and formalise it. |
| Career support built in (CV, interview, portfolio) | Rare in the local market and a real differentiator. |
| Certificate tied to stated attendance and assessment rules | The correct principle. It now needs published numbers. |
| A+, CCNA and Data Analysis already offered | A ready-made specialisation layer sitting above the core program. |

### 3.2 Gaps found — and what this model does about them

| # | Gap in the current offering | Impact | Fix in this model |
|---|---|---|---|
| 1 | The nine modules are described only as themes ("computer fundamentals", "networking", "data skills"). No names, no hours, no outcomes. | Students cannot compare MPC with a competitor; instructors teach inconsistently; certificates cannot be defended. | Section 4: 14 named courses, each with a code, hours, outcomes, project and assessment. |
| 2 | **Linux is absent from the core.** | The graduate profile requires Linux installation and administration. Employers with servers, ISPs and hosting companies will not hire without it. | **IT-201 Linux Installation & System Administration (54 h)** made core, not optional. |
| 3 | **Web design, web development, hosting and domains are listed as "optional specialisations, where instructors and equipment permit."** | This is the most requested and most sellable skill set in Mogadishu, and it is half of what the program must deliver. Leaving it optional makes it unreliable. | Terms 3 and 4 make web design, frontend, PHP/MySQL and hosting **core — 168 hours combined**. |
| 4 | **No programming language anywhere in the core.** | "Basic IT engineer" now means someone who can write a script. Without programming a graduate cannot automate, cannot progress, and cannot enter development work. | **IT-303 Programming Foundations with Python (36 h)** added as core. |
| 5 | **No version control anywhere.** | No employer in software will hire someone who has never used Git. It is also how MPC proves a project was really built by the student. | **IT-302 Git & GitHub for Developers (18 h)** added, plus a version-control requirement in every programming course (Section 4.1). |
| 6 | No separate frontend course — JavaScript was buried inside "web design". | Students learn to lay out a page but not to make it work, and arrive at server-side development unprepared. | **IT-401 Frontend Development (48 h)** sits between web design and web development. |
| 7 | No published prerequisite chain or course order. | Students enrol in the wrong course, drop out, or repeat content. | Section 5: a fixed sequence with explicit prerequisites and a dependency map. |
| 8 | No per-course certificate. | A student who completes one course leaves with nothing to show, so short-course revenue is lost. | Section 6: MPC Course Certificate for every unit, plus four stage awards. |
| 9 | Security is not named anywhere. | Employers now ask about it; it is also the fastest-growing course category. | **IT-203 IT Security & Data Protection Essentials (36 h)** added as core. |
| 10 | No stated weekly hours, total hours or credit value. | Cannot be recognised by employers, ministries, or partner institutions. | 12 hours/week × 48 teaching weeks = **576 contact hours**, mapped per course. |
| 11 | A+, CCNA and Data Analysis are sold separately with no relationship to the program. | Students do not know where these fit or whether they duplicate the program. | Section 8: a specialisation layer that sits **after** the diploma, with duplicate content removed. |
| 12 | No lab or equipment specification. | Quality varies by campus and by intake. | Section 9: minimum lab requirements per course. |
| 13 | Practical exams are implied but not defined. | "Practical assignments instead of theory alone" is a claim without a mechanism. | Section 6.3: every course ends in a timed practical exam on real equipment. |

### 3.3 Two recommendations that change the business, not just the syllabus

**A. Sell the same courses three ways.** Build the catalog once, then package it as (a) the 12-month diploma, (b) the 6-month intensive, and (c) individual short courses. One set of materials, three price points, three audiences. Section 7 shows the mapping.

**B. Make the 6-month intensive an exit point of the 12-month program, not a separate product.** Today they are described as two different programs. If the 6-month program is exactly Terms 1 and 2 delivered at 24 hours/week, then a 6-month graduate can return later and continue into Terms 3 and 4 with full credit. That converts a one-time student into a returning one.

## 4. The Course Catalog

**Total: 14 courses · 576 contact hours · 4 terms of 12 weeks · 12 hours per week**

Each course is independently certificated. Codes follow `IT-<term><number>`.

### 4.1 Standing rule — version control in every programming course

From IT-302 onward, **every project in every programming course is submitted as a GitHub repository, not as a folder or a zip file.** This applies to IT-303 (Python), IT-304 (Web Design), IT-401 (Frontend), IT-402 (Web Development) and IT-404 (Capstone).

Each of those courses carries a **5% "version control" component** inside its project mark, assessed on:

- The repository exists, is public, and has a written `README.md` explaining what the project does and how to run it.
- Commits are frequent and incremental — a project pushed in a single commit on the deadline scores zero for this component.
- Commit messages describe the change ("add login validation"), not the day ("update", "final", "final2").
- `.gitignore` correctly excludes passwords, configuration files and vendor folders.
- The student can demonstrate `git log`, `git branch`, `git merge` and recovery of an earlier version on request in the practical exam.

By graduation every student has a GitHub profile with at least five real repositories. That profile is a portfolio an employer can inspect before the interview, and it is the single cheapest employability gain in the whole program.

#### IT-101 · Computer Hardware & IT Essentials
**48 hours · No prerequisite · Aligned to CompTIA ITF+ and A+ Core 1**

*What the student can do at the end:* strip and rebuild a desktop PC, name and test every component, and correctly diagnose a machine that does not power on or does not display.

**Topics**

1. How a computer works: CPU, RAM, storage, motherboard, power supply, cooling.
2. Number systems and units: binary, hexadecimal, bits vs bytes, storage and speed measurement.
3. Inside the case: identifying motherboard form factors, chipsets, expansion slots, connectors.
4. Storage: HDD vs SSD vs NVMe, partitions, file systems, health checking.
5. Memory: types, capacity, dual channel, diagnosing bad RAM.
6. Power: PSU wattage, voltages, surge protection, UPS sizing for a Somali office with unstable mains.
7. Peripherals and ports: USB standards, HDMI/VGA/DisplayPort, printers, scanners, projectors.
8. Mobile and laptop hardware: batteries, screens, keyboards, common repairs.
9. Safety and workshop practice: ESD, tools, cable management, workspace discipline.
10. Structured troubleshooting: the six-step method, isolating a fault, documenting a repair.

**Practical labs:** full disassembly and reassembly (×3, timed) · POST beep-code diagnosis · RAM and disk swap · PSU test · faulty-machine triage station (instructor plants 10 faults, student finds them).

**Course project:** *Bench Repair Log* — diagnose and repair five faulty machines, with a written fault report for each (symptom, diagnosis, action, result, parts, time).

**Assessment:** Practical exam 40% · Labs 30% · Written test 20% · Attendance 10%

#### IT-102 · Windows Installation, Configuration & Troubleshooting
**60 hours · Prerequisite: IT-101 · Aligned to CompTIA A+ Core 2**

*What the student can do at the end:* install Windows 11 on a bare machine from USB, configure it fully for a business user, and repair a Windows installation that will not start.

**Course project:** *Office PC Build-Out* — take three bare machines to a documented, business-ready state: OS, drivers, accounts, office software, antivirus, backup, printer, and a signed handover checklist.

**Assessment:** Practical exam 45% · Labs 30% · Written test 15% · Attendance 10%

#### IT-201 · Linux Installation & System Administration
**54 hours · Prerequisite: IT-102 · Aligned to CompTIA Linux+ (introductory level)**

*What the student can do at the end:* install Ubuntu Server, manage it entirely from the command line, and run it as a file, print and web server for a small office.

**Topics**

1. What Linux is and where it is used; distributions; choosing Ubuntu LTS.
2. Installing Ubuntu Desktop and Ubuntu Server; partitioning, LVM basics, swap.
3. Dual-boot and virtual machines (VirtualBox / Hyper-V) as a safe practice environment.
4. The shell: navigation, paths, `ls cd pwd cp mv rm mkdir find`, wildcards, tab completion.
5. Files and text: `cat less head tail grep nano vim`, redirection and pipes.
6. Users and groups: `useradd usermod passwd groups`, `/etc/passwd`, `sudo` and `visudo`.
7. Permissions: `chmod chown`, octal notation, umask, special bits.
8. Packages: `apt`, repositories, updates, `.deb` files, `snap`.
9. Processes and services: `ps top kill systemctl journalctl`, enabling services at boot.
10. Storage: `df du mount fstab`, adding and formatting a second disk, USB media.
11. Networking on Linux: `ip`, netplan, static addressing, `ping ss dig`, hostname resolution.
12. Remote administration: SSH, key-based login, `scp`, basic firewall with `ufw`.
13. Services: Samba file sharing to Windows clients, CUPS printing, Apache web server.
14. Scheduling and shell scripting: `cron`, a first bash script, backup automation with `tar` and `rsync`.
15. Logs and troubleshooting: where logs live, reading them, recovering a system that will not boot.

**Practical labs:** install Ubuntu Server from ISO · build a Samba share that Windows PCs can map · SSH-only administration day (no GUI allowed) · write a nightly backup script and schedule it · break-and-fix: instructor corrupts fstab/permissions, student recovers.

**Course project:** *Small Office Linux Server* — deliver an Ubuntu Server providing shared folders with per-department permissions, a shared printer, an internal website, automated nightly backups, and SSH admin access — with written documentation.

**Assessment:** Practical exam 45% · Labs 30% · Written test 15% · Attendance 10%

#### IT-202 · Network Fundamentals & Cabling
**54 hours · Prerequisite: IT-101 · Aligned to CompTIA Network+ (N10-009)**

*What the student can do at the end:* design, cable, address and troubleshoot a small office network.

**Topics**

1. What a network is; LAN, WAN, MAN; client-server vs peer-to-peer.
2. The OSI and TCP/IP models used as a troubleshooting tool, not a memory exercise.
3. Media and cabling: UTP categories, fibre basics, coax, wireless; distance limits.
4. Hands-on cabling: straight-through and crossover, RJ45 crimping, punch-down, patch panel, cable tester, labelling standards.
5. Devices: hub, switch, router, access point, modem, firewall — what each actually does.
6. Ethernet and switching: MAC addresses, ARP, collision vs broadcast domains, basic VLAN concept.
7. IPv4 addressing: classes, private ranges, subnet masks, gateway; **subnetting practice until fluent**.
8. IPv6 introduction: address format, why it exists, dual stack.
9. DHCP: how leases work, configuring a scope, reservations, troubleshooting.
10. DNS: resolution process, record types (A, CNAME, MX, TXT), `nslookup`/`dig`, hosts file.
11. NAT and port forwarding; public vs private addressing.
12. Common protocols and ports: HTTP/HTTPS, FTP/SFTP, SSH, SMTP/IMAP, RDP, SNMP.
13. Wireless: standards, frequencies, channels, WPA2/WPA3, coverage planning, interference.
14. Internet access in the Somali context: ISP links, routers, failover between two providers, bandwidth sharing.
15. Troubleshooting method: `ping tracert ipconfig/ip nslookup netstat`, working layer by layer.
16. Documentation: network diagram, IP address plan, cable schedule.

**Practical labs:** make and certify 20 cables · build a 3-switch network and prove connectivity · subnet a /24 for five departments and implement it · DHCP and DNS configuration · Wi-Fi survey and channel selection · fault-injection lab (instructor plants 8 network faults).

**Course project:** *Network Design Pack for a 30-User Office* — floor plan, cable schedule, device list with costing, IP address plan, VLAN/department layout, and a working scaled-down build in the lab.

**Assessment:** Practical exam 40% · Labs 30% · Subnetting test 15% · Attendance 10% · Design documentation 5%

#### IT-203 · IT Security & Data Protection Essentials
**36 hours · Prerequisites: IT-102, IT-202 · Aligned to CompTIA Security+ awareness level**

*What the student can do at the end:* secure a small office to a defensible baseline and explain the risks to a non-technical owner.

**Topics**

1. Why attacks happen: threat actors, motives, and what actually targets small businesses.
2. The CIA triad in plain language; risk = likelihood × impact.
3. Passwords and identity: password rules that work, password managers, MFA, account lockout.
4. Social engineering: phishing, vishing, fake invoices, WhatsApp scams, mobile-money fraud — with local examples.
5. Malware: viruses, worms, trojans, ransomware; how infection actually happens; response procedure.
6. Endpoint hardening: patching, antivirus, disk encryption (BitLocker/LUKS), screen lock, USB policy.
7. Network security: firewall rules, changing default credentials, disabling WPS, segmenting guest Wi-Fi, VPN basics.
8. Web and email security: HTTPS and certificates, SPF/DKIM/DMARC introduction, spam filtering.
9. Physical security: server room, locks, CCTV, visitor control, secure disposal of disks.
10. Backup as a security control; ransomware recovery drill.
11. Data protection and privacy: what personal data is, retention, consent, confidentiality for a client's data.
12. Incident response for a small business: detect, contain, eradicate, recover, learn; who to call.
13. Writing a one-page IT security policy an owner will actually sign.
14. Professional ethics: the technician's power over client data, and the boundaries that go with it.

**Practical labs:** phishing-email identification drill · hardening checklist applied to a real lab PC and audited by a peer · ransomware simulation and restore-from-backup race · router hardening.

**Course project:** *Security Assessment & Policy* — assess a supplied (deliberately weak) office setup, produce a findings report with severity ratings, remediate what can be remediated in the lab, and deliver a one-page signed security policy.

**Assessment:** Practical exam 35% · Assessment report 35% · Labs 20% · Attendance 10%

#### IT-302 · Git & GitHub for Developers
**18 hours · Prerequisite: IT-201 (comfortable on the command line) · Taken before all programming courses**

*What the student can do at the end:* keep every project under version control, publish it to GitHub, recover any earlier version, and work on a shared repository with other people without losing work.

This course is short and it is not optional. Everything a student writes from here to graduation lives in a Git repository.

**Topics**

1. The problem Git solves: `final.php`, `final2.php`, `final_REAL_final.php` — and what happens when two people edit the same file.
2. Installing Git on Windows and Linux; Git Bash; configuring `user.name` and `user.email`.
3. The three areas: working directory, staging area, repository. `git init`, `git status`, `git add`, `git commit`.
4. Writing commit messages a colleague can read; commit size and frequency.
5. History: `git log`, `git show`, `git diff`; seeing exactly what changed and when.
6. Undoing work safely: `git restore`, `git revert`, `git reset` — and which one is dangerous.
7. `.gitignore`: keeping passwords, `config.php`, `node_modules` and `.env` out of the repository. **Why a leaked database password on GitHub is a real incident.**
8. Branching: `git branch`, `git switch`, why you never develop on `main`.
9. Merging and merge conflicts: causing one deliberately, reading the markers, resolving it, committing the resolution.
10. GitHub: creating an account and a professional profile; SSH keys; public vs private repositories.
11. Remotes: `git remote add`, `git push`, `git pull`, `git clone`, `git fetch`.
12. Collaborating: forking, pull requests, code review comments, issues, project boards.
13. Writing a `README.md` in Markdown: what the project is, screenshots, how to install and run it.
14. GitHub Pages: publishing a static site straight from a repository, free.
15. Recovering from the four common disasters: committed a password, committed to the wrong branch, deleted a file, pulled and overwrote your work.
16. Using Git inside VS Code, and when to drop back to the command line.

**Practical labs:** version a small project through 20 commits · deliberate merge-conflict resolution (in pairs) · recover a file deleted three commits ago · collaborate in groups of four on one repository via pull requests · publish a personal profile page to GitHub Pages.

**Course project:** *Your GitHub Profile* — a public GitHub account with a profile README, an SSH key configured, and one repository containing an earlier MPC project with a clean commit history and a full README. This repository becomes the root of the student's portfolio.

**Assessment:** Practical exam 45% (performed live at the terminal) · Repository quality 35% · Labs 10% · Attendance 10%

#### IT-303 · Programming Foundations with Python
**36 hours · Prerequisites: IT-201, IT-302**

*What the student can do at the end:* write a working Python program from a plain-English description, and automate a repetitive IT task with a script.

Python is taught first, before JavaScript and PHP, because its syntax gets out of the way while the student learns to *think* like a programmer. It is also the language they will use to automate the systems work they learned in Terms 1 and 2.

**Topics**

1. What a program is; how code becomes behaviour; installing Python and VS Code; running a script from the terminal.
2. Variables, data types (`int`, `float`, `str`, `bool`), and converting between them.
3. Input and output; formatting with f-strings.
4. Operators and expressions; integer vs float division; operator precedence.
5. Conditions: `if`, `elif`, `else`, comparison and logical operators; nested conditions.
6. Loops: `for`, `while`, `range`, `break`, `continue`; building a loop that does not run forever.
7. Lists: indexing, slicing, appending, removing, sorting, iterating.
8. Dictionaries, tuples and sets; choosing the right structure for the data.
9. Strings: slicing, `split`, `join`, `strip`, `replace`, searching, case handling.
10. Functions: defining, parameters, default values, return values, scope; why a 200-line script should be five functions.
11. Errors and debugging: reading a traceback, `try`/`except`, validating user input, `print` debugging.
12. Files: reading and writing text files; reading and writing CSV; working with folders using `os` and `pathlib`.
13. Modules and packages: `import`, the standard library, `pip`, virtual environments (`venv`).
14. JSON and APIs: `json`, `requests`, fetching live data and using it in a program.

#### IT-401 · Frontend Development — JavaScript & Interactive Interfaces
**48 hours · Prerequisites: IT-303, IT-304**

*What the student can do at the end:* make a website do things — validate, calculate, filter, animate, remember, and fetch live data from an API.

This is the course that turns a page designer into a frontend developer, and it comes **before** server-side web development so that students arrive at PHP already able to program the browser.

**Topics**

1. What JavaScript is, where it runs, and how it differs from Python (which the student already knows).

16. **`fetch()` and APIs:** requesting JSON, handling loading and error states, rendering live data (weather, currency rates, prayer times) into the page. This is the bridge to IT-402.

#### IT-402 · Web Development with PHP, MySQL & JavaScript
**60 hours · Prerequisites: IT-401**

*What the student can do at the end:* build and deploy a real database-driven web application that a business can use, with a JavaScript-driven interface on top of it.

**Topics**

1. Client vs server; what a server-side language does; installing XAMPP; `htdocs`, virtual hosts, ports.
2. PHP basics: syntax, variables, types, operators, `echo`, string and array functions.
3. Control structures, functions, and including files (`include`/`require`) for reusable headers and footers.
4. Arrays in PHP: indexed, associative, multidimensional; `foreach`.
5. Forms and superglobals: `$_GET`, `$_POST`, `$_SERVER`; sanitising and validating input on the server as well as in the browser.
6. Sessions and cookies; building login and logout; protecting pages; roles (admin vs user).
7. Databases and relational thinking: tables, rows, primary and foreign keys, normalisation to 3NF in plain terms, ER diagrams.
8. SQL: `CREATE`, `INSERT`, `SELECT`, `WHERE`, `ORDER BY`, `LIMIT`, `UPDATE`, `DELETE`, `JOIN`, `GROUP BY`, `HAVING`, aggregate functions.
9. phpMyAdmin and the MySQL command line; designing the schema before writing any code.
10. Connecting PHP to MySQL with PDO; **prepared statements, and why SQL injection must be prevented**.
11. Full CRUD: list, search, paginate, add, edit, delete, with confirmation and validation.
12. File uploads: images and documents, type and size checking, safe storage, displaying them.
13. **JavaScript on top of PHP** — the integration this course exists to teach: `fetch()` calling a PHP endpoint that returns JSON; live search that queries the database as the user types; add-to-cart and delete without reloading the page; form validation in the browser *and* on the server; loading and error states.
14. Building a small JSON API in PHP: endpoints, HTTP methods, status codes, returning JSON safely.
15. Reports: filtering by date, totals and subtotals, printable output, exporting to CSV and PDF.
16. Web application security: password hashing (`password_hash`/`password_verify`), XSS escaping on output, CSRF tokens, access control by role, safe error handling that does not leak information, keeping credentials out of Git (links to IT-302).
17. Code organisation: separating configuration, logic and presentation; a simple MVC-style folder structure; naming conventions.
18. WordPress in practice: installing, themes, plugins, pages, menus — and delivering a client site fast when a custom build is not justified.
19. Testing your own application: what to try to break, a release checklist, and debugging a live application.

**Practical labs:** build the same CRUD three times, faster each time · SQL query drills against a supplied database · AJAX live-search exercise · harden a deliberately vulnerable application supplied by the instructor.

**Course project:** *Database-Driven Business Application* — a complete working system chosen from: student registration and results, clinic appointments, shop inventory and sales, or property/rental management. Must include role-based login, full CRUD, at least one JavaScript/AJAX feature that works without a page reload, search, at least one report, file upload, and a populated demo database. **Developed on branches in a GitHub repository with a full README and setup instructions.**

**Assessment:** Practical exam 35% · Application project 40% (including 5% version control) · SQL test 15% · Attendance 10%

### 5.2 Why this order and not another

- **Hardware before software.** A student who has never opened a case cannot diagnose a boot failure. IT-101 must be first.
- **Windows before Linux.** Students arrive knowing Windows. Linux is easier once installation, partitioning and file systems are already understood in a familiar environment.
- **Office software early, and in parallel.** IT-103 has no technical prerequisite and gives students a sellable skill in the first three months. It also keeps less confident students engaged while the hardware content is demanding. This is deliberate retention design.
- **Networking after operating systems.** Configuring an IP address means little until you have installed the OS that holds it.
- **Security straight after networking.** You cannot secure a network you do not understand, and the habits must be formed before students start writing code that handles passwords.
- **Git before any programming.** This is the change that matters most in this revision. If Git is taught after the first programming course, students spend that course forming habits they must then unlearn. Eighteen hours spent here saves the same students from losing a week's work later, and gives every subsequent project a visible, gradeable history.
- **Python before JavaScript and PHP.** Python's syntax stays out of the way while the student learns loops, functions and data structures — the concepts, not the punctuation. JavaScript and PHP are then a matter of learning new syntax for ideas already understood, rather than learning both at once. Python also pays for itself immediately by automating the Linux and networking work from Term 2.
- **Web design before frontend before web development.** Structure (HTML/CSS), then behaviour (JavaScript), then data (PHP/MySQL). A student who meets PHP before JavaScript ends up copying code without understanding what runs where — the single most common failure in self-taught web developers.
- **Frontend as its own course.** Making JavaScript a full 48-hour course rather than a chapter inside web design is what makes "Junior Frontend Developer" a realistic job title for a graduate.
- **Hosting after the application exists.** There is nothing to deploy until IT-402 is done.
- **Capstone last, and it must span both halves of the program** — this is what makes the graduate a *broad* junior IT engineer rather than either a repair technician or a web designer.

## 6. The Certificate Model

This is the part the current MPC page leaves open, and it is where most of the commercial value sits.

### 6.1 Five levels of award

| Award | Requirement | What it says |
|---|---|---|
| **MPC Course Certificate** | Pass any single course | "Completed *Office Productivity & Digital Documents*, 36 hours, with grade B." Issued for every course, including to students who enrol in that course alone. |
| **MPC Certificate — Computer & Office Operations** | Term 1 complete (IT-101, 102, 103 — 144 h) | Can install and support Windows PCs and produce professional business documents. Employable as an office assistant or lab technician. |
| **MPC Certificate — IT Support, Networking & Security** | Terms 1 + 2 complete (288 h) | The **6-month intensive exit award.** Can support Windows and Linux machines, build a small network, and secure it. |
| **MPC Certificate — IT Infrastructure & Programming** | Terms 1 + 2 + 3 complete (432 h) | Can deploy a complete office network with servers and printing, program in Python, use Git and GitHub, and build a responsive website. |
| **MPC Professional Diploma in Information Technology (Junior IT Engineer)** | All 14 courses + capstone passed (576 h) | The full award. Infrastructure, frontend and backend development, with a defended capstone and a public GitHub portfolio. |

**Design principle:** every stage is a real exit point with a real award. A student who runs out of money after six months still leaves with a certificate that names skills an employer recognises — and with a documented path back in.

### 6.2 Requirements for any certificate

A certificate is issued only when **all four** conditions are met:

| Condition | Threshold |
|---|---|
| Attendance | **≥ 75%** of scheduled contact hours for that course |
| Overall course grade | **≥ 60%** |
| Practical exam | **≥ 60%** — a failed practical cannot be compensated by written marks |
| Course project | Submitted, accepted, and added to the student's portfolio — **as a GitHub repository for every programming course** |

For the Diploma, additionally: **all 14 courses passed**, capstone passed at ≥ 60%, and the panel presentation delivered.

### 6.3 Assessment structure — the same shape in every course

| Component | Typical weight | Form |
|---|---|---|
| Practical exam | 35–50% | Timed, on real equipment or a real machine. The student *does* the task; the examiner scores the outcome against a checklist. |
| Course project | 25–40% | The portfolio piece described in each course above. In programming courses, 5 of these percentage points are the version-control mark (Section 4.1). |
| Continuous labs | 10–30% | Weekly lab sheets, signed off by the instructor. |
| Written / knowledge test | 10–20% | Multiple choice and short answer, aligned to certification objectives. |
| Attendance | 5–10% | Recorded per session. |

**Rule:** no course is assessed by written examination alone. Every course ends with the student performing the job task.

### 6.4 Grading scale

| Grade | Marks | Meaning |
|---|---|---|
| A — Distinction | 85–100 | Works independently; quality an employer would accept without rework. |
| B — Merit | 70–84 | Competent; needs occasional guidance. |
| C — Pass | 60–69 | Meets the minimum standard for the task. |
| F — Fail | below 60 | Must repeat the course or the failed component. |

**Re-sits:** one re-sit permitted per course, within four weeks, capped at grade C. A second failure requires repeating the course.

### 6.5 What is printed on the certificate

Front:

- Student full name and MPC student number
- Award title (course name or stage award)
- Contact hours and dates of study
- Grade achieved
- Unique certificate number and QR code linking to an online verification page
- Signatures: Programme Director and Principal, plus the MPC seal

Back (or attached transcript):

- The list of learning outcomes achieved
- The component marks
- The project title completed, **and the URL of its GitHub repository** for programming courses

**Recommendation:** build the verification page on mpc.so (`mpc.so/verify/<certificate-number>`). It costs one small database table, and it is the difference between a certificate an employer trusts and one they do not. It is also a natural build exercise for IT-402 students.

### 6.6 Attendance and progression policy (suggested wording for publication)

- Sessions are 2.5 hours; attendance is taken at the start and after the break.
- Below 75% attendance in a course: no certificate for that course, regardless of marks. The course may be repeated once at 50% fee.
- Three consecutive unexplained absences trigger a counselling meeting with the Programme Director.
- A student who fails two courses in the same term repeats the term.
- Fees, if paid per term, must be cleared before certificates for that term are released.

### 8.1 How the core courses map to international exams

**Note for the printed prospectus:** exam codes and versions change. Confirm the current codes with CompTIA and Cisco before printing. At the time of writing the current versions are A+ **220-1201 / 220-1202** (V15), Network+ **N10-009**, Linux+ **XK0-006**, and CCNA **200-301 v1.1**.

### 8.2 Specialisation courses — Level 2, after the Diploma

MPC already advertises CompTIA A+, CCNA 200-301 and Data Analysis. Position them, and the new courses below, explicitly as **Level 2**: taken after the Diploma, or by candidates who already have equivalent experience.

| Specialisation | Hours | Prerequisite | Leads to |
|---|---|---|---|
| **Python & Django Web Development** | 90 | IT-303, IT-402 | Python/Django developer, backend developer |
| **Data Analysis** (Advanced Excel, SQL, Power BI, Python pandas) | 90 | IT-103, IT-303 | Data analyst, MIS officer |
| CompTIA A+ Exam Preparation | 48 | IT-102 | A+ certified technician |
| Cisco CCNA 200-301 | 120 | IT-202 | Network engineer, ISP roles |
| Cybersecurity Practitioner | 90 | IT-203 | SOC analyst, security officer |
| Modern JavaScript Frameworks (React) | 90 | IT-401 | Frontend developer |
| Cloud Fundamentals (AWS / Azure) | 60 | IT-201, IT-202 | Cloud support associate |
| Graphic Design & Digital Marketing | 60 | IT-103 | Designer, social media officer |

Removing the duplication is the key move: because IT-102 and IT-202 already cover most of A+ and Network+, and IT-303 already covers Python, the Level 2 courses become short, focused and high-margin rather than full re-teaches.

### 8.3 Django — where it sits, and why

Python is core (IT-303) and ends with a two-session Django introduction, so every graduate has seen what a web framework is and what Django does. **The full Django framework is a Level 2 specialisation, not a core course.**

The reason is arithmetic, not preference. Teaching Django properly — models, migrations, views, templates, forms, the admin site, authentication, the ORM, REST APIs and deployment — takes 60 to 90 hours. Within a 576-hour year that can only be bought by cutting PHP/MySQL, the frontend course, or the infrastructure half of the program, and all three are worse trades:

- PHP still runs the large majority of small-business and freelance web work in the local market, and it is what shared cPanel hosting supports by default. It is where a graduate's first paid job comes from.
- The Django course is far stronger when taken *after* IT-402, because the student already understands routing, databases, sessions, authentication and MVC. Taught cold, the same 90 hours produce a student who can follow a tutorial but cannot debug.

**If MPC decides Django must be core**, the clean way to do it is to run the program at 15 hours/week (720 hours over the same 48 weeks) and add *Django Web Framework (60 h)* to Term 4. That decision affects the timetable and the fee, not the structure of this document — the sequence is unchanged, one course is added at the end.
